Project Documentation

镇定学习工具箱

基于可学习度量与 Lyapunov 候选函数的控制学习工具箱。统一 Env、 Algo、Runner 三层，覆盖状态控制、轨迹跟踪、观测器、 视觉伺服与接触推动。

Python 3.10+ PyTorch Gymnasium MuJoCo Env / Algo / Runner
快速开始 → 查看架构 命令参考
Env

物理与任务

状态、观测、动作边界、真实转移、成功与终止判据。9 个注册任务，另有 RGB、观测器、圆盘、网格和 SO101 专用环境。

Algo

度量与控制

表征、正定度量 M、策略、Critic、损失与优化器。支持模型梯度、PPO、离散 SAC、解析控制和 RGB 变体。

Runner

训练与报告

preflight、采样、预热、更新、验证、冻结、独立测试、快照和报告。每个实验使用独立输出目录。

共同数学对象

所有任务共享同一个候选函数结构：在误差或特征坐标中学习正定度量 M，用它构造二次型候选函数，并记录一步下降量。

\[ V_\theta(e,c)=e^\top M_\theta(e,c)e,\qquad M_\theta(e,c)\succ0 \]
\[ D_\theta(s,a)=V_\theta(s')-V_\theta(s),\qquad M=LL^\top+\varepsilon I \]

模型梯度、PPO、离散 SAC 或解析交互矩阵把 M 转成控制量；闭环样本再用来更新表征、度量或性能估计器。RGB 书稿实现使用带系数的形式：

\[ V=\tfrac12 e^\top M e,\qquad e=\frac{\phi(I)-\phi(I^*)}{4} \]
\[ J_*=\frac14\left.\frac{\partial\phi}{\partial I}\right|_{I^*}L_I(I^*,\hat Z,K) \]
\[ H=J_*^\top MJ_*+0.01\operatorname{diag}(J_*^\top MJ_*)+\eta I,\qquad u=\operatorname{sat}\left(-\lambda H^{-1}J_*^\top Me\right) \]
读法 V 是候选函数，不是全局稳定性证明；训练和报告关注物理误差、到达时间、输入成本与真实 V 变化。

架构：Env、Algo、Runner

仓库把物理环境、学习算法与实验调度分开。Env 不依赖学习库；Algo 不负责采样流程；Runner 负责把两者接起来，并保存完整的实验记录。

扩展口诀 新任务写 Env；新算法写 Algo；新实验流程写 Runner。三者通过明确的接口契约连接，不互相替代。

快速开始：质点训练与配对评价

先跑最短的免外部资产流程，确认安装、接口和输出目录都正常。

python -m stabilization_learning train \
  --config configs/public/point_mass_smoke.json \
  --output runs/point_mass_demo

python -m stabilization_learning evaluate \
  --run runs/point_mass_demo --seeds 20001 20002

产物

  • model.pt 与训练历史
  • evaluation.json
  • 同一组起点上比较学习 M 与单位 M

换成自己的实验

  • 复制 point_mass_smoke.json
  • 改 epochs、episodes、seed
  • 输出目录用新名称
短配置只用于接口检查 point_mass_smoke.json 只有 4 条训练回合；要观察训练效果，换成更长的预算。

Python API

需要自定义采样、损失或诊断时，可以直接调用 Env 与 Algo。

from stabilization_gym import make
from stabilization_learning import StabilizationLearner, TrainConfig

env = make("point_mass", max_steps=50)
learner = StabilizationLearner(
    env,
    config=TrainConfig(episodes=4, batch_episodes=2, epochs=1),
    env_id="point_mass",
    env_kwargs={"max_steps": 50},
)
learner.train("runs/point_mass_api")
env.close()

正式多种子、多任务实验仍建议使用统一的 Runner：它负责冻结、独立测试、快照和报告。

统一 v4 工作流

统一 Runner 把一次实验拆成固定阶段。每个实验使用新的输出目录；测试发生在全组模型冻结之后。

写配置。 复制一个模板，声明 jobs[]、backend、任务、种子、预算与测试变体。
preflight。 检查 schema、任务名、seeds、输出路径、Python 与初始化。
train。 初始验证 → 采样/预热 → epoch 更新 → 验证 → 全组冻结 → 独立测试。
快照。 确认进程退出、写锁释放后，采集运行快照。
report。 读取快照生成独立报告、曲线和审计记录。

preflight

python scripts/run_unified_training_v4.py preflight \
  --config configs/public/unified_cpu_smoke.json \
  --output runs/v4_preflight.json

train

python scripts/run_unified_training_v4.py train \
  --config configs/public/unified_cpu_smoke.json \
  --output runs/v4_demo

快照与报告

python scripts/capture_linux_run_snapshot.py \
  --run runs/v4_demo --output runs/v4_process.json

python scripts/run_unified_training_v4.py report \
  --root runs/v4_demo --output runs/v4_report \
  --process-snapshot runs/v4_process.json --compact

--compact 无损压缩曲线，不删除模型或原始记录。报告通常包含 selected、initial、identity、fixed_M 等测试变体。

配置怎么写

一个最小 unified v4 配置：

{
  "schema": "unified_training_v4",
  "maximum_minutes": 60,
  "minimum_free_gib": 5,
  "jobs": [{
    "id": "state_point_mass",
    "backend": "state_model_gradient",
    "config": {
      "task": "point_mass",
      "seed": 41,
      "total_updates": 256,
      "batch_size": 16,
      "hidden": 64,
      "scales": [1.0],
      "validation_seeds": [10001],
      "test_seeds": [20001],
      "physical": {"max_steps": 50}
    },
    "schedule": {"epochs": 8, "certificate_updates": 1}
  }]
}
字段作用
schema固定为 unified_training_v4
maximum_minutes / minimum_free_gib整组实验的时间与磁盘资源门限
jobs[]一个任务一个 job；多个 job 共享资源门限
backend选择算法后端，如 state_model_gradient、episode_ppo、rgb_legacy
config任务名、种子、更新数、batch、hidden、初态尺度、物理步数
scheduleepoch 数、表征/Critic 预热、证书更新次数
test_variants可选：selected、initial、identity、fixed_M

Push / SO101 联合成本

python "$CLI" push-train \
  --config configs/joint_certificate_v2/push_overnight.json \
  --costs configs/joint_certificate_v2/push_costs.json \
  --time-bank runs/calibration/time_bank.json \

  --seeds 81 --output runs/demo_push/group.json --max-hours 0.1
python "$CLI" push-test --run runs/demo_push/train \
  --group-manifest runs/demo_push/group.json \
  --output runs/demo_push/test --repeats 16 --max-hours 1

  --group-manifest runs/demo_push/group.json \

2. 接配置

  • 在配置里声明 task、seed、预算
  • 复制现有模板，保留 schema 与 jobs 结构

3. 选或写 backend

  • 先复用现有 6 个后端之一
  • 需要新损失/梯度时再写 create_training_backend

4. 测试

  • 单测物理边界与动作约束
  • 冻结后做配对测试

GMM-D：局部增量模型

GMM-D 把状态—动作分区后拟合非负局部增量增益，预测形式为：

\[ \Delta=a\sum_k h_k(x,a)\,b_k,\qquad b_k\ge 0 \]
环节接口 / 实现状态

待做多维 GMR、v4 backend、配置注册待实现

L 学习：拉格朗日动力学

L 学习拟合机械系统的拉格朗日结构，再用误差能量和跟踪控制器生成广义力。它不是 Lyapunov critic 的 LAC，也不是现有神经 M 训练。

\[ L(q,\dot q)=\tfrac12\dot q^\top M_{\mathrm{mass}}(q)\dot q-P(q) \]
\[ \hat\tau=M_{\mathrm{mass}}(q)\ddot q+C(q,\dot q)\dot q+g(q) \]
环节接口状态
数据MechanicalTrainingBatch(q, velocity, acceleration, applied_force, ...)接口已就绪
拟合LagrangianFitter → LagrangianDynamics待实现
模型mass_matrix、coriolis_matrix、potential、gravity、inverse_dynamics接口已就绪
控制LLearningController + MechanicalReference待实现
能量LLearningEnergy待实现
待做结构模型、训练器、跟踪控制器、积分补偿、v4 backend待实现

常见问题

现象处理
ModuleNotFoundError激活正确的 venv；先安装两个核心库
CUDA 不可用重装与驱动匹配的 PyTorch；检查 torch.cuda.is_available()
MuJoCo 导入失败安装 requirements-simulation.txt；检查 GL 后端
输出目录已存在换新目录；不要覆盖旧实验
显存不足减小 batch_size / num_envs；先跑 smoke 配置
preflight 失败按 JSON 报错修配置、任务名或路径，再重跑
进程未退出就 report等写锁释放，再用快照脚本采集
